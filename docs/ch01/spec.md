# 第 1 章 Spec：Spec 驱动开发流程

## 背景与目标

为 TUICodingAgent 后续章节建立统一的开发门禁：每章依次阅读启动提示词和正文，先形成 Spec、Plan、Task、Checklist，再实施和验收。

## 功能需求

- F1：每章在编码前明确需求、架构、任务顺序和可观测验收项。
- F2：四份文档逐层覆盖，需求能追溯到实现任务和验证证据。
- F3：开发后运行自动化测试和真实终端端到端对话。
- F4：验收报告区分通过、未通过和受环境限制的项目。

## 非功能需求

- N1：中文文档和中文注释。
- N2：先取得运行证据再更新完成状态。
- N3：项目名称统一为 TUICodingAgent。

## 不做的事

- 第 1 章不定义具体产品功能；产品能力由第 2–15 章分别定义。

## 验收标准

- AC1：第 2–15 章均存在 Spec、Plan、Task、Checklist。
- AC2：每章实现后有自动化或端到端证据。
- AC3：未具备真实 API、tmux 等外部条件时明确记录，不伪造通过。
