# TUICodingAgent 工具系统 Spec

## 背景与目标

第 2 章已完成纯文本多协议流式对话。第 3 章使 TUICodingAgent 能由模型选择并执行工具，将结果回灌后生成一次最终答复，从聊天客户端升级为可完成真实工作的单轮 Agent。

目标包括：统一工具抽象与注册中心；读、写、改、命令、glob、内容搜索六个核心工具；超时和结构化错误；OpenAI/Anthropic 双协议工具定义、流式参数拼接和结果回灌；Claude Code 风格工具行；一次工具执行后的续答。本章不实现连续 Agent Loop。

## 功能需求

- F1：每个工具公开名称、描述、JSON Schema 和异步执行入口；注册中心支持登记、按名查找及导出 OpenAI/Anthropic API 工具定义。
- F2：实现六个固定工具：带行号和上限的读文件；自动创建父目录并覆盖的写文件；原文唯一匹配的改文件；带 stdout/stderr/exit code/超时的命令；glob 文件查找；返回文件、行号和内容的正则搜索。
- F3：每次初始对话请求注入六个工具定义，系统提示词说明 Agent 与工具约定。
- F4：双协议流式解析正文、丢弃思考内容，并按 index/id 拼接一个或多个工具调用的名称和 JSON 参数碎片；JSON 错误转为结构化工具错误。
- F5：按模型声明顺序执行全部工具调用；未知工具、参数错误、超时和执行异常均返回结构化结果，不中断会话。
- F6：把 assistant 工具调用及对应结果以协议正确格式追加历史，再请求一次最终答复。若第二次仍返回工具调用，不执行并以单轮上限提示结束。
- F7：OpenAI 与 Anthropic 对上层暴露相同的工具调用、结果与运行时事件语义。
- F8：TUI 实时展示 `● 工具名(关键参数)`、成功/失败摘要和截断标识，并保留在 scrollback。
- F9：所有失败同时以结构化结果回灌并在 UI 使用可区分样式；应用继续接受下一轮。

## 非功能需求

- N1：命令和潜在长耗时工具受内置超时保护，超时终止并返回结果。
- N2：工具在 Worker/异步线程中执行，TUI 可滚动且不冻结。
- N3：两种协议的触发、展示、回灌和错误行为一致。
- N4：参数缺失/类型错误、非法正则、路径/命令错误、JSON 碎片错误均不得产生未捕获异常。
- N5：读文件、命令输出、glob 和搜索命中均有明确体量上限及截断标记。
- N6：工具定义、结果、错误和日志不得泄露 API 密钥。

## 不做的事

- 多轮连续工具 Agent Loop、权限确认、执行沙箱和路径白名单。
- 工具取消、持久化、折叠展开、自定义/配置化工具集、配置化超时。
- 多模态结果和同轮工具并行优化。

## 验收标准

- AC1：注册中心包含六工具，可按名查找；双协议请求均含六个正确定义。
- AC2：读现有文件返回带行号内容；不存在文件返回结构化错误。
- AC3：写工具创建/覆盖文件并自动创建父目录。
- AC4：改工具对 1、0、多个匹配分别成功或返回带匹配数错误。
- AC5：命令返回 stdout/stderr/exit code；超时被终止且会话不挂死。
- AC6：glob 返回匹配文件；搜索返回文件/行/内容。
- AC7：分片工具名/JSON 参数被完整拼接为工具调用。
- AC8：端到端“读文件并总结”完成调用、回灌和最终文本续答。
- AC9：第二阶段再请求工具时不执行第二轮，以单轮上限结束。
- AC10：双协议运行相同工具任务，上层行为一致。
- AC11：TUI 展示工具行、摘要、截断和 scrollback。
- AC12：不存在文件、非零命令、改文件无匹配均回灌结构化错误，UI 可区分且会话继续。
- AC13：大文件、长命令输出和海量搜索结果被截断。
